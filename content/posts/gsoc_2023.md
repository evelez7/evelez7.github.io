During the summer of 2023 I had the opportunity to work on Clang for Google Summer of Code.
I worked on ExtractAPI which is a neat feature that extracts symbols from source and serializes them into some format.
It's currently used for documentation but can be adapted to other things.
My project focused on adding C++ support.

If you want a quick summary, here's my [final submission](https://summerofcode.withgoogle.com/archive/2023/projects/uBg3dUrw)
which links to my final report.

# What is ExtractAPI?
ExtractAPI uses Clang's syntax tree to gather up all the symbols in a source 
file into an intermediate format before spitting a serialized copy.

For example, the following:
```cpp
class Foo {
  public:
    static int getBar();
};
```

*getBar* will be stored in an internal structure that recognizes it as a static method member of Foo.
Foo will be a top level record that houses all of its internal **public** members.
Foo might also be part of a namespace or it might be a public nested class.

# Why is ExtractAPI?
ExtractAPI was [proposed](https://discourse.llvm.org/t/rfc-clang-support-for-api-information-generation-in-json/58845)
as a method to serialize source symbols without needing to dig around the AST.
ExtractAPI's doesn't directly generate documentation like other tools, which is its main strength.

# What did I do?
## Community Bonding Phase
GSoC has a "community bonding" phase before the "real" coding phase starts.
During that time, I refactored ExtractAPI's AST visitor to follow the [curiously recurring template pattern](https://en.wikipedia.org/wiki/Curiously_recurring_template_pattern).
Clang's AST visitor already follows that pattern, so it seemed natural for us to follow the pattern as well.
Before, ExtractAPI would visit fields and methods in ad-hoc fashion; when a class was visited, it would check if fields or methods existed and capture them.
Now, they were just captured when we reached them in the AST.

[Take a look at the archived Phabricator review.](https://reviews.llvm.org/D151477)

## C++ Support
I added support for C++ [classes and their members](https://reviews.llvm.org/D157007), 
[templates, template specializations, concepts](https://reviews.llvm.org/D157076)
and [namespaces](https://reviews.llvm.org/D158239).

The basic formula for most of these constructs was as follows:
1. Add a visitor method (`VisitCXXRecordDecl`).
2. Rebuild its source declaration (`class Foo;`).
3. Add a method to the `SymbolGraphSerializer` to output the information to the JSON file.
